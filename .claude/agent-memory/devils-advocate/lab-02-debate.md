## คำถามที่ยังต้องตอบก่อน ship

1. repo จะ public หรือ private — เนื้อหาใน `docs/` ยอมให้ใครก็อ่านได้จริงไหม
2. ข้อความจากฟอร์ม contact ใครอ่าน และเก็บไว้นานแค่ไหน
3. deploy แล้ว SQLite อยู่รอดไหม (ไม่ mount volume = หายทุกครั้งที่ deploy)
4. ถ้านายจ้างปัจจุบันเปิดเว็บนี้วันนี้ มีบรรทัดไหนที่เจ้าของจะเสียใจ

## บทเรียนวิธีทำงาน

- **ค้านด้วย path + เลขบรรทัดเสมอ** — ข้อโต้แย้งที่ถูกรับเป็น D-id ทุกข้อในรอบนี้ มาจากการเปิดไฟล์จริง ส่วนข้อที่ค้านแบบหลักการล้วน (เสนอให้ตัดเรื่อง AI ทิ้ง) ถูกตีตกและผมถอนเอง
- **แยกความเสี่ยงจริงออกจากความไม่สวยงาม** — ที่ดันให้เป็น P0 ได้คือข้อที่มีคนเสียหายจริงเมื่อเกิด ไม่ใช่ข้อที่แค่ดูไม่ดี
- **"ไม่ลิงก์จาก nav" ไม่เท่ากับ "เข้าไม่ได้"** — ต้องปิดที่โค้ดด้วยเสมอ
- ฟีเจอร์ที่ยังพังอยู่ไม่ใช่ฟีเจอร์ที่ปลอดภัย — ต้องแก้ก่อนที่มันจะเริ่มทำงาน ไม่ใช่หลังจากนั้น เพราะถึงตอนนั้นจะไม่มีใครจำได้

## เส้นที่ห้ามข้าม

- ห้ามเขียน payload โจมตีที่ใช้ได้จริง หรือ token ลงเอกสารในคอร์สนี้ — อธิบายชนิดของช่องโหว่พอ
- ห้ามแก้โค้ดเอง — รายงานแล้วให้เจ้าของตาม ownership เป็นคนแก้ (UI = Claude `frontend` · API/SQLite = OpenCode `backend`)
